# 01 情報の境界と守ること

状態：下書き（2026-11-20 の決定の整理）。決めたことは [11-decisions.md](11-decisions.md)。

## 1. 持つもの・持たないもの

| 区分 | 内容 |
|---|---|
| 持つ | 年齢、性別、暦日（受診・入退院・記載・検査の日時。CA-004）、診断、問題、経過の記載、バイタル、検査値、処方・注射（一般名）、処置、自分の考え |
| 持たない | 患者ID、氏名、イニシャル、生年月日、住所、電話番号、メール、施設の実名、医療者の個人名（CA-003・CA-005） |
| どこにも持たない | 患者ID と記録の対応（台帳。CA-007） |
| 取り込まない | カルテ画面の撮影、スクリーンショット、OCR、画像・波形そのもの（CA-008） |

- 施設名は「当院」「近医」「前医」。医療者は役割（自分・上級医・他科・看護など）だけ。
- Casebook との違い：暦日をそのまま持つ。粒度が細かい。この2つで、年齢・性別・日付・経過の組み合わせから患者が分かる見込みは、Casebook より高い。だから、保存の守り（4）を Casebook より厚くする。

## 2. 匿名化の網（CA-003・CA-006）

入力は手入力（CA-008）なので、最初の網は「打たない」。そのうえで、打ってしまった分を、次の順で落とす。

| 順 | 網 | 何をするか |
|---|---|---|
| 1 | 打たない | 画面に常時、「氏名・ID は入れない」を出す |
| 2 | AI の選別 | 氏名・ID・生年月日・住所・連絡先・施設の実名・医療者の名前を、AI が**場所として指す**。AI は文を書き換えない。サーバーが、指された場所だけを決まった語（「〔氏名〕」「当院」など）に置き換える |
| 3 | 保存の前の決定論の検査 | 置き換えた後の文と、整理した事実のすべての文字に、形の検査（電話・メール・郵便番号・12桁以上の数字）をかける。残っていれば、その場所だけを置き換えてから保存する（入力は捨てない）。置き換えた種類と件数だけを、画面に出す |

- **送る前に、止めない・伏せない**（CA-013）：打った文は、そのまま AI に渡る。
- **AI に届きうるもの**【事実】：打った文のすべて。氏名や電話番号を打てば、それも Anthropic の API に届く。RAG の「識別情報らしき文字は送らない」より広い。これは CA-006・CA-013 の決定の中身。だから、1 の「打たない」が主の網になる。
- **保存されるもの**：置き換えた後の文と、そこから整理した事実だけ。打った原文そのものは、保存もログもしない（サーバーのメモリにあるのは、その1回の処理の間だけ）。
- 2 を「場所を指すだけ」にする理由：AI に文を書き直させると、臨床の中身（数値・否定・時刻）が変わりうる。置き換えを決定論にすれば、保存される文は「原文から、指された場所を置き換えたもの」と、機械的に確かめられる。
- 3 を形の検査だけにする理由：暦日をそのまま持つ（CA-004）ので、日付の形は止められない。生年月日かどうかは文脈で決まるので、2 の AI に任せる。
- AI の選別が失敗した（答えが返らない・形が合わない）ときは、その文を保存しない。打った文は画面に残し、もう一度送れる。**選別を通っていない文を、保存しない**。

実装（段1）の細目（`packages/core/src/select/selection.ts`・`guard/shapes.ts`・`text/fold.ts`、`apps/worker/src/intake.ts`）：

- **送る前の整え**：見えない書式の文字（ゼロ幅の空白など）を除き、改行をそろえ、前後の空白を落とす。ほかの文字は変えない（全角・半角も、そのまま保存する）。
- **AI が返す種類**：氏名、医療者の名前、ID・番号、生年月日、住所、連絡先、施設の名前、勤務先・学校などの固有名。置き換える語は、表で決まる（〔氏名〕〔医療者〕〔ID〕〔生年月日〕〔住所〕〔連絡先〕〔固有名〕。施設は、当院・近医・前医・他院、分からなければ〔施設〕）。
- **引用の確かめ**：文にある（全角・半角の違いは、そろえて探す）、2字以上・60字以内、改行をまたがない、数字だけの引用は数字が4つ以上（短い数を、文じゅうで置き換えない）で、ほかの数の一部には当てない。**1つでも確かめられなければ、全体を失敗にする**（識別情報が残るかもしれない文を、通さない）。
- **形の検査は、Casebook の匿名化リンタより狭い**：見つけた場所を置き換えて保存するので、臨床の数値を誤って置き換えないことを優先する。郵便番号は「〒」つきだけ（3桁-4桁の、範囲の書き方〔尿量の幅など〕を、郵便番号とみなさない）、4桁ずつ区切った12桁は見ない（4桁の値を3つ並べた書き方を、番号とみなさない）、暦日は見ない。「〒」のない郵便番号・住所は、2 の AI の仕事。
- **整理（段2）で AI に送るもの**：保存した文（識別情報を置き換えた後）だけ。選別のときに送った文より、増えるものはない。整理の答えから、文にない字は記録に入らない（docs/03 の 3）。
- **草案（段4）で AI に送るもの**：保存した文から決定論で切り出した引用（問題ごとの A・P の区切り、その問題の記載に書かれた投薬・できごと）と、問題の名前・日時・病日だけ。草案は保存もログもしない。AI の文は記録に入らない（docs/03 の 3）。
- **問題の筋のつなぎ（段3a）で AI に送るもの**：すでに保存した問題の名前と、その記載がある1行（保存した文の一部）だけ。AI が返すのは記号（どれとどれが同じか）だけで、名前・字は記録に入らない（docs/04 の 9）。
- **測ること**：AI の選別の落とし漏れは、架空の文での評価（docs/03 の 3）で数える。目標は 0。**0 を保証する仕組みではない**（AI が指さなかった氏名は、記録に残る）。だから、1 の「打たない」が主の網。

## 3. リポジトリに置いてはいけないもの

- 実在の患者に由来するデータ。作業ツリーのどこにも置かない（.gitignore に頼らない）。
- 実在の施設名、人名、患者を思わせる具体的な記述（コード・コメント・テスト・コミットメッセージ・PR）。
- API キー・トークン。
- テストと見本は、架空症例だけ（`synthetic: true`）。
- 守りの本体は、Casebook の phi-guard を写して使う（実装の最初の段で入れる）。

## 4. 保存の守り（CA-011）

- 入口は、本人だけ。使うたびのログインは求めない（CA-016）。方式は CD-012（案：端末の登録を1回だけ）。
- **入口の鍵がまったくない作りにはしない**。鍵の設定がないときは、すべてを断る（鍵なしで動かさない）。
- 記録の中身を、ログに出さない。
- 書き込みの一覧（どの表に何を書くか）を [04-data-model.md](04-data-model.md) に置き、試験で固定する。
- 暗号化の方式は CD-004、保持と消し方は CD-005。

## 5. 外へ出るもの

- 出るのは、Anthropic の API だけ（CA-012）。何を送るかは、機能ごとに docs に書く。
- 解析、テレメトリ、外部フォント、CDN は使わない。
- 他の人への共有・提供・公開は作らない。

## 6. 事故のとき

実データらしきものが、コミット、PR、ログ、会話に入ったことに気づいたら、次の順で動く。

1. 作業を止め、本人に知らせる（その文字列を引用・要約・出力しない）。
2. 本人の判断で、履歴の書き換えやリポジトリの扱いを決める。エージェントは自分で履歴を書き換えない。
