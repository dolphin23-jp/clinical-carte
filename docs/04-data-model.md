# 04 データモデル

状態：段2 まで実装した（患者・受診・取り込んだ文・区切り・測定値・投薬・できごと・問題）。訂正の履歴・問題の結びつきは、まだ案。**実装した分と、案との違いは 7・8**。変えてはいけないのは、2 の約束と、6 の書き込みの一覧の考え方。

## 1. 実体の一覧

```
患者 patients
  └─ 受診 encounters（救急・外来・入院）
        ├─ 取り込んだ文 sources ……… 正本（層①）
        │     └─ 区切り segments ……… 文のどこが、どの見出しか（層③の材料）
        ├─ 測定値 observations ……… バイタル・検査（層②）
        ├─ 投薬 medications ………… 処方・注射（層②）
        ├─ できごと events ………… 処置・手術・検査の実施・コンサルト・転棟・急変（層②）
        └─（患者に付く）問題 problems … 問題・診断（層②）
```

- 層④（フローシート・推移・時間軸・問題別・見出し）は、保存しない。上から計算する。
- 「記載」（救急記録・外来・入院時初診・プログレスノート・サマリー）は、別の表を持たない。**取り込んだ文と、その区切り**で表す（3.3）。

## 2. 約束

1. **AI は文を作らない**：保存する文は、本人が打った文（から識別情報の場所を置き換えたもの）だけ。AI が出すのは、場所（引用）と、分類と、構造だけ。
2. **事実は、出どころを持つ**：測定値・投薬・できごと・問題は、どの文のどの範囲から来たかを持つ。本人が画面で直接入れたものは、出どころが「本人」。
3. **書かれていないことは、行にしない**：陰性・正常・「なし」を、補って作らない。
4. **本人の訂正は、整理し直しより強い**：本人が直した行は、AI が整理し直しても変えない。直す前の値は、履歴に残す。
5. **日時は、書かれたものだけ**：文に書かれた日時か、本人が指定した日時。分からなければ空（「日時不明」として並べる）。「今日」「昨日」などは、本人が指定した記載の日から、決定論で直す。AI に日時を作らせない。
6. **別の患者へ移さない**：行は、作ったときの患者・受診から動かさない（間違えたら、消して入れ直す）。

## 3. 表（案）

### 3.1 患者 `patients`

| 列 | 内容 |
|---|---|
| id | ULID |
| age, age_on | 年齢（歳の整数）と、その年齢だった日。いまの年齢は、ここから概算して出す。**生年月日は持たない** |
| sex | 性別 |
| background | 既往・常用薬（一般名）・アレルギー・生活歴・家族歴（文。取り込んだ文への参照を持てる） |

- 氏名・ID・呼び名・病室の欄は、ない（CA-003・CA-014）。
- **自動の見出し**（CA-014。保存しない）：`72歳 男 ｜ 2026-11-18 入院 ｜ #市中肺炎` の形。年齢・性別・いちばん新しい受診の開始日と種類・いちばん上の問題から作る。

### 3.2 受診 `encounters`

| 列 | 内容 |
|---|---|
| id, patient_id | |
| kind | 救急 / 外来 / 入院 |
| start, end | 開始・終了の日時（暦日のまま。CA-004） |
| from_encounter | 救急から入院になったとき、元の救急の受診 |
| outcome | 転帰（文。入院・外来の終わり方） |

- 外来は、1回の受診が1行。入院は、入院から退院までが1行。
- 病日は保存しない（`start` から計算する）。

### 3.3 取り込んだ文 `sources` と、区切り `segments`

`sources`

| 列 | 内容 |
|---|---|
| id, patient_id, encounter_id | |
| kind | 救急記録 / 外来初診 / 外来再診 / 入院時初診 / 経過（プログレスノート）/ 中間サマリー / 退院サマリー / 看護記録 / 検査結果 / バイタル / レポート（画像・病理・培養など）/ 処方・注射 / 紹介状・他院の情報 / **自分のメモ** / その他 |
| in_chart | 病院のカルテにあるものの写しか、carte だけの記録（自分のメモ）か |
| author_role | 自分 / 上級医 / 他科 / 看護 / その他 / 不明（名前は持たない。CA-018） |
| at | 記載・実施の日時（2 の 5） |
| entered_at | 取り込んだ時点 |
| text | 識別情報の場所を置き換えた後の文（docs/01 の 2） |
| replaced | 置き換えた種類ごとの件数（整数だけ） |
| organized | 整理の状態（まだ / 済み / 失敗）と、整理に使った指示の版 |

`segments`

| 列 | 内容 |
|---|---|
| source_id, start, end | 文の中の範囲 |
| label | 見出し（主訴 / 現病歴 / 既往 / 身体所見 / 検査 / S / O / A / P / 方針 など。記載の型ごとに決めた集まり） |
| reason | `label` が「整理できなかった部分」のとき、その理由 |

- **記載の表示**は、文を、区切りの見出しで並べ直したもの。文字は1字も変えない。
- 区切りは、いつでも作り直せる（文が正本）。
- 本人は、文を直せる。直したら、その文から作った区切りと事実を作り直す（本人が直した事実は残す。2 の 4）。

### 3.4 測定値 `observations`（バイタル・検査）

| 列 | 内容 |
|---|---|
| id, patient_id, encounter_id | |
| at | 測定・採取の日時 |
| name | カタログの項目（あれば） |
| name_raw | 書かれた名前（カタログにない項目も、書かれた名前のまま記録する。捨てない） |
| value | 数（あれば） |
| comparator | 不等号（`<` `>` など。あれば） |
| value_text | 定性の結果（`(-)` `2+` など）・数で表せない結果 |
| unit | 単位（書かれていれば。桁を、値の大きさから当てない） |
| source_id, start, end | 出どころ |
| origin | 読み取り（決定論）/ AI / 本人 |

- **値を判定しない**：基準範囲・色・矢印・警告の列は、ない。
- 数の読み取りは決定論（Playbook の `readLabText` を出発点にする）。Playbook は不等号・定性を読まなかった（受け渡しの契約が数だけだったため）が、carte は記録なので、書かれたとおりに持つ。
- 読めなかった部分は、区切り（`segments`）に「整理できなかった部分」として残す。

| 列 | 内容 |

- 用量を数に分けないのは、計算に使わないため（用量の計算・確認は、carte の仕事ではない）。時間軸（いつからいつまで）には、名前と `action` と日時で足りる。

## 4. 日時の形

- `YYYY-MM-DD` か `YYYY-MM-DDTHH:mm`（日本の時刻。時刻帯の変換をしない）。日だけ分かるときは、日だけ。
- 分からないときは空。**推測で埋めない**。一覧では「日時不明」としてまとめる。

## 5. AI の答えの形と、確かめ方（要点）

AI が返すのは、次の3つだけ（構造化した出力）。

1. **識別情報の場所**：種類と、文の中の引用。
2. **文の区切り**：見出しと、文の中の引用。
3. **事実の案**：種類・名前・日時・値と、その出どころの引用。

サーバー（と同じ core の関数）が確かめる。通らないものは事実にせず、「整理できなかった部分」に残す。

| 確かめること | 内容 |
|---|---|
| 引用が文にある | 一字一句。なければ捨てる（場所が決まらない） |
| 数値が引用にある | 事実の数は、引用の中の数字そのもの。AI が計算・換算した数は通さない |
| 日時が引用にある | 2 の 5 |
| 値が種類の受け付ける形 | zod で検証 |
| 同じ場所から、食い違う2つの事実 | 両方を事実にしない |
| 識別情報の形 | 保存の前の検査（docs/01 の 2） |

## 9. 段3a で作ったもの（問題の筋。CA-024・CA-025）

作った表は、`apps/worker/migrations/0004_threads.sql`。つなぎの計算と見方は、`packages/core/src/problems/threads.ts`。

| 表・列 | 中身 |
|---|---|
| `problem_threads` | id・patient_id・display_name・merged_into。患者ごとの「問題の筋」。**文の字を持たない**（display_name は、その筋に書かれた名前から本人が選んだものだけ。打った名前は入らない）。統合した筋は消さず、統合先を持つ（id を使い回さない） |
| `problems` に足した列 | thread_id（筋。まだつないでいなければ NULL）・thread_origin（rule：名前が同じ／ai：AI が指した／self：本人が直した）・activity（resolved：解決／inactive：非活動・既往と書かれている。書かれていなければ NULL） |
| `history` | id・patient_id・at（日本の日時。分まで）・action（move・merge・name）・target（直した行の id）・before・after（筋の id か、選んだ名前）。**文は入らない** |

- **つなぐ時**：文を整理したあと（同じ要求の中で）。名前が同じ（先頭の番号「#1」・全角半角・空白の違いを除いて）筋が1つだけあれば、決定論でつなぐ。それ以外は、AI に聞く（すでに筋があるか、名前の違う記載が2つ以上あるとき）。AI に送るのは、すでにある筋の、書かれてきた名前（6 つまで）と、新しい記載の名前と、その記載の行（保存した文の1行。200 字まで）だけ（docs/01 の 2）。答えは記号（T1・M1）で、知らない記号・自分自身・1つの記載への2つの答え・食い違う2つの筋は使わない。答えのない記載は、新しい筋（同じ名前どうしは1つ）。
- **AI に聞けないとき**（1日の上限・失敗）：決定論でつなげない記載は、つながないまま残す。画面の「AI でつなぐ」で、あとからつなげる（AI の1回に数える）。本人が1件ずつ行き先を選んでもよい。
- **整理し直したとき**：同じ場所・同じ名前の記載は、前と同じ筋のまま（本人が直したものも、self のまま）。
- **文を消したとき**：その文の問題の行は消える。筋の行は残る（記載がなくなった筋は、見えなくなるだけ）。患者を消すと、筋と履歴も消える。
- **見方**（`threadViews`）：筋ごとに記載を古い順に並べ、名前の移り変わり（同じ名前は1回）、いちばん新しい記載の確からしさと、解決・非活動を出す。いちばん新しい記載が「否定的」なら「否定的と書かれたもの」、解決・非活動なら「解決・非活動と書かれたもの」、それ以外は「いまの問題」。判定ではなく、書かれたとおりの並べ分け。
- **問題ごとの A・P**（`problemNotes`）：問題の記載が「#問題」の見出しの区切りにあれば、次の見出しまで（S・O・A・P が続くあいだ）の A・P・A/P の区切り。A・P・A/P の区切りの中にあれば、その区切り。字は保存しない（場所だけ。画面が保存した文から切り出す）。
- **直す操作**：記載を別の筋へ移す・新しい筋に分ける（`PATCH /api/problems/:id`。いまの筋を添え、違えば 409）、筋を統合する・表示の名前を選ぶ（`PATCH /api/threads/:id`）。どれも `history` に残る。別の患者の筋へは移せない。
- **まだないもの**：`problem_links`（問題と値・薬・できごとの結びつき。段3c）。問題以外の事実を直す操作。

## 10. 段3e で作ったもの（事実を直す）

作った表と列は、`apps/worker/migrations/0005_fact_edits.sql`。直しの形は、`packages/core/src/record/edits.ts`。

| 表・列 | 中身 |
|---|---|

## 11. 本人の調節で作ったもの（CA-029）

作った列と表は、`apps/worker/migrations/0006_user_edits.sql`。形と確かめは、`packages/core/src/record/edits.ts`・`problems/threads.ts`。

| 表・列 | 中身 |
|---|---|
| `problem_threads` に足した列 | status_override（本人が決めた確からしさ）・activity_override（active：いまの問題・resolved・inactive）・ord（並び）・excluded（外した）・typed_name（打って直した名前。**選別を通した後の字**） |
| `segments` に足した列 | origin（ai・self。本人が足した・見出しを直した区切りは self） |
| `user_edits` | id・patient_id・at・target_type・target・field・before・after。選んだ値・日時・名前だけ。**文を打ち直したときは、前後の文を残さない**（before・after は NULL：紛れた識別情報を消すための直しがありうる） |

- **本人の行が先**：本人が足した・直した行（origin = self）は、整理し直しでも消さない。AI の答えのうち、本人の行と同じ場所・同じ字の行は足さない（段3e の「引き継ぎ」を、この形に置き換えた）。区切りは、本人の区切りと同じ場所から始まる AI の区切りを足さず、終わりは全部を並べて決め直す。
- **統合**：記載を動かさず、統合先（merged_into）を持つだけにした。見方は統合先にまとめ、統合先から解ける。段3a の作りで統合したもの（記載を動かしたもの）は、解いても記載は戻らない。
- **なぞって足す**：字は保存した文のその場所のもの（選別を通し直さない）。前後の空白を詰め、1行の中・200 字まで・識別情報の形がないこと。値は、なぞった字を決定論で読めるときだけ（数を AI に写させない決まりと同じ）。足した問題は、名前が同じ筋があればそこへ、なければ新しい筋。
- **打って直す（C-1）**：問題の名前と文の打ち直しは、文を入れるときと同じ選別（`intake`）を通し、置き換えた後の字だけを保存する（AI の1回。選別が失敗したら保存しない）。文を打ち直すと、AI の行は消して整理し直し、本人の行は、前の文の字を新しい文で探して場所を移す（見つからなければ消し、数を画面に出す）。
- **値の項目名**：検査名の表（取り込んだ名前と carte の足し分）からだけ選べる。表にない名前は断る。
