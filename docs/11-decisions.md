## 2. 未決のこと

推奨は、設計者（エージェント）の案。決めるのは本人。

| 番号 | 問い | 推奨と理由 |
|---|---|---|
| CD-001 | 送る前の決定論の検査が、識別情報の形（電話・郵便番号・メール・長い数字・敬称つきの人名）を見つけたとき、**止める**か、**伏せて進める**か | 伏せて進める（その部分を「〔伏せた〕」に置き換え、種類と件数だけを画面に出す）。全患者を手入力する量では、止めるたびに打ち直すと続かない。RAG は「止める」だった |
| CD-002 | **患者の見分け方**：台帳がないので、一覧で患者を見分ける手がかりが要る | 自動の見出し（年齢・性別・入院日・主な問題）と、本人が付ける短い呼び名。**病室・ベッドの番号は入れない**（院内では患者を特定できる） |
| CD-003 | **AI が患者を割り振るか**：数人分をまとめて貼って、AI に分けさせるか | 割り振らせない。先に患者を選んでから入れる。別の患者の記録が混ざるのが、カルテで最も重い誤り |
| CD-004 | **保存の守り方**：(a) Cloudflare Access を必須にして D1 に保存、(b) (a) に加えてサーバーの鍵で暗号化、(c) 端末の合言葉で暗号化（サーバーは読めない） | (a) から始める。(c) は最も堅いが、サーバーでの横断検索と AI の整理が、端末の側の仕事になり、合言葉を失うと全部を失う。(b) は、アカウントを取られたときには効かない |
| CD-005 | **保持の期間と消し方**：自動で消すか。異動・退職のあと、どうするか | 自動では消さない（長く持つことが目的）。患者ごとに消せる。暗号化した書き出し（控え）を作れる |
| CD-006 | **使う端末と、つながらないときの入力** | 未定。端末（電話・タブレット・PC）で画面の作りが変わる。つながらないときの入力は、後の段でよい |
| CD-007 | **他の医療者の記載**：写すか。写すなら、だれの記載かをどう残すか | 写す。著者は役割だけ（自分・上級医・他科・看護など）。名前は持たない。自分の判断と他者の判断を混ぜないために、役割は要る |
| CD-008 | **取り込んだ文（識別情報を落とした後）を残すか** | 全文を残す。AI の整理の出どころになり、将来のモデルで整理し直せる。貼った原文そのものは、保存もログもしない |
| CD-009 | **画像・波形**（X線・CT・心電図の画像そのもの） | 持たない（CA-008 の延長）。所見の文と数値だけ |
| CD-010 | **過去の患者をさかのぼって入れるか** | 未定。入れられる作りにはする（暦日をそのまま持つので、順序は崩れない） |
| CD-011 | **モデル・費用・1日の上限** | 実装のときに決める。使うたびに、何を送るかを docs に書く |

## 3. 前提

- 勤務先の規程との関係は、本人が判断して進める（2026-11-20）。Casebook の前提（A-009：匿名化した症例を個人で保管する分には許可されている）と比べて、carte は粒度が細かく（日々の経過・全検査）、暦日をそのまま持つ。この前提が崩れたら、保存の範囲を見直す。
- carte は、診療の正本ではない。正本は病院のカルテ。carte の値は「ある時点の写し」で、最新とは限らない。
