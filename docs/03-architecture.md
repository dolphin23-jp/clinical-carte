# 03 構成と、作る順序

状態：下書き（案）。実装はまだない。

## 1. 構成（案）

| 部分 | 中身 |
|---|---|
| `packages/core` | 純関数だけ（DOM・保存・通信・時計・乱数に触れない）。型と検証（zod）、識別情報の形の検査、検査値・バイタルの読み取り、日時の扱い、AI の答えの確かめ、見方（フローシート・推移・時間軸・自動の見出し）の計算 |
| `apps/worker` | Cloudflare Workers。入口の鍵、API、保存（D1）、Anthropic の API の呼び出し |
| `apps/web` | 画面（React＋Vite の PWA）。iPhone・iPad・PC（CA-017） |

- TypeScript（strict）、pnpm workspaces、Vitest と fast-check、ESLint で core の境界を止める（Casebook・Playbook・Atlas と同じ）。
- **検査と確かめの関数は core に1つだけ**：画面もサーバーも、同じ関数を import する。RAG では画面（JS）とサーバー（TS）が別の実装で、同じ試験の入力を両方に通して揃えていた（双子）。carte は最初から1つにする。
- 保存は Cloudflare D1（CA-011）。RAG と同じ基盤で、本人のアカウントにある。
- phi-guard とフックは、Casebook から写す。試験と見本は、架空症例だけ。

## 2. 入口（CA-016・CD-012 の案）

- 端末ごとに最初の1回、長い合鍵を入れる。サーバーは、長い期限の印（画面のプログラムからは読めない Cookie）を出す。以後、ログインの画面は出ない。
- 合鍵はサーバーの秘密に置き、リポジトリに置かない。端末の印は、端末ごとに別で、別の端末から外せる。
- 鍵の設定がないときは、すべての API を断る。
- iPhone・iPad では、ホーム画面に足したアプリと Safari とで、印の置き場が別になる【推論。実装のときに実機で確かめる】。使う側で1回ずつ登録する。

## 3. AI の呼び出し（CA-012）

- 呼ぶのはサーバーだけ。キーはサーバーの秘密。画面には出さない。
- 構造化した出力で、場所（引用）・区切り・事実の案だけを返させる（docs/04 の 5）。文を書かせない。
- モデル・費用・1日の上限は CD-011。指示は1か所に集め、変えるときは、変更の前後で、架空の文での評価を見る。
- 送るものは、機能ごとに docs に書く。段1・段2 で送るのは、その1回に打った文と、患者の年齢・性別・受診の種類・記載の日だけ（ほかの記録は送らない）。

## 4. 複数の端末（CA-011）

- サーバーの記録が1つの正本。端末は、読んで表示するだけで、記録を端末に保存しない（段5 までは）。
- 行ごとに版（`rev`）を持ち、違っていれば上書きせずに知らせる（RAG の症例の記録と同じ）。取り込んだ文は追記が主なので、ぶつかることは少ない。
- つながらないときの入力は、後の段（CD-006）。

## 5. 作る順序（案）

| 段 | 内容 | 使えるようになること |
|---|---|---|
| 0 | 骨組み：3つの部分、型検査・リンタ・試験・phi-guard、D1 の表、入口の鍵、常時の帯（「写し・最新とは限らない／氏名・ID は入れない」） | まだ使えない |
| 1 | 患者・受診を作る。文を入れる → AI の選別（識別情報の場所）→ 置き換え → 形の検査 → 保存。検査値・バイタルの決定論の読み取り。時系列の一覧と、検査の表 | **実際の入力を始められる最小**。選別が入るまでは、実データを入れない |
| 2 | AI の整理：文の区切り（記載の型）、事実の案（投薬・できごと・問題）、確かめ、「整理できなかった部分」。フローシート、検査の推移、投薬の時間軸 | カルテとして読める |
| 3 | 記載の型ごとの表示（救急・外来・入院時・経過・サマリー）。自分のメモ。問題別の見方。本人の訂正と履歴 | 振り返りに使える |
| 4 | 要約・サマリーの草案、記録への質問（出どころの範囲を引く）。入力の状態の一覧（数えるだけ） | |
| 5 | 患者をまたぐ検索。書き出し（控え）。つながらないときの入力 | |

- 段1 と同じ段で、**選別の評価の道具**を作る：新しく書いた架空の文（名前・施設名・連絡先を、実行時に組み立てて混ぜる）で、落とし漏れを数える。目標は漏れ 0。
- 各段の終わりに、「いま作らないもの」を docs/11 に足す。
