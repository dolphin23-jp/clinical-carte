# 受け渡しパケット（Playbook → Casebook）

状態：**Casebook 側は実装済み（T012、T028。決めた細部は A-027、A-041）**。Playbook 側は実装を始めるところ。この文書は、Casebook と Playbook の両 repo に**同じ文面**で置き、版を合わせて直す。パケットの形は版 1 のまま（T028 で変えたのは、運ぶ経路と、受け取りの操作だけ。**T041a で、項目の種類「背景（`history`）」を足した**：追加だけで、版は上げない。A-051。**T044 で、項目の任意の欄「来院後の経過分（`afterMin`）」を足した**：追加だけで、版は上げない。A-054。**T046 で、治療の任意の欄「構造化の欄」〔名前・種類・部位・用量・終える開始〕を足した**：追加だけで、版は上げない。A-057。**T048 で、プロブレム・所見・治療の任意の欄「身体の領域（`region`）」を足した**：追加だけで、版は上げない。A-059。**T050 で、項目の任意の欄「プロブレムへの紐づけ（`problemId`）」を足した**：追加だけで、版は上げない。A-061。**T059 で、パケットの任意の欄「架空症例（`synthetic`）」を足した**：追加だけで、版は上げない。A-070。**古い Casebook は、この欄つきのパケットを、パケットの形が違うものとして全体を拒む**〔外側の形が厳密なため。項目の欄の追加とは違う〕ので、Casebook を先に更新してから送る）。

## 1. 目的と原則

- Playbook の session から、半年後にも残したい情報だけを、Casebook の症例へ送る（A-004）。
- 全入力の自動保存はしない。送るのは、**前回の送信からの差分**から、本人が選んだ項目だけ。
- 検査値や所見は、**原本の値をそのままコピー**する。AI が数値を転記・要約する経路は作らない。
- パケットは匿名化済みのテキスト。クリップボードや共有シートで運んでよい。

## 2. 運ぶ方法

- 形式：JSON を UTF-8 にし、base64url にして、先頭に `CBH1:` を、末尾に `.` と CRC-32（16進8桁。base64url の本体の UTF-8 に対する値）を付ける。貼り付けの途中切れと文字の取り違えを検出する。貼り付けの途中の空白・改行は無視する。
- 目標：**送る側の「Casebook へ送る」を1回押し、受け取る側で確認画面の「取り込む」を1回押す**（A-041）。経路は、使えるものを上から順に使う。どれでも、受け取り側の確認画面（4 節）は同じ。
- **受け渡し箱**（経路 0。A-042）：Playbook と Casebook は同じオリジンで配信し、共有の保存先（IndexedDB）の「箱」に、パケットを置く。Casebook が開いたとき（または画面が見えるようになったとき）に、自動で「届いています」と出す。取り込んだあとは、症例コードが、Playbook に自動で返る。決まりは [handoff-box.md](handoff-box.md)。箱が使えない端末では、下の経路 1〜3 で運ぶ（Playbook は、箱に置くと同時に、クリップボードにもコピーする）。

| 順 | 経路 | 送る側（Playbook） | 受け取る側（Casebook） |
|---|---|---|---|
| 0 | **箱** | `outbox` に置く（handoff-box.md） | 開いたとき・画面が見えるようになったときに読み、「届いています」を出す |
| 1 | **リンク** | パケットを、クリップボードにコピーしたうえで、Casebook の `https://<Casebook の URL>/#cbh=<パケット>` を開く。パケットは、`#` 以降（フラグメント）に入れる。フラグメントはサーバに送られない | 起動時と `hashchange` で読み、すぐ URL から消す（履歴に残さない）。確認画面を、読んだ状態で出す |
| 2 | **クリップボード** | 「送る」を押した操作の中で、`navigator.clipboard.writeText` で、パケットをコピーする | 一覧の「Playbook から受け取る」を押したとき**だけ**、`readText` で読み、確認画面を、読んだ状態で出す。ふだんは読まない |
| 3 | **貼り付け** | （2 と同じ） | 受け取り画面の入力欄に貼る。いつでも使える |

- **iPhone・iPad の注意**【推論・未確認。A-021】：ホーム画面に追加した PWA は、Safari と保存先が別で、別オリジンの PWA 同士も直接は通信できない。ホーム画面の PWA から別オリジンのリンクを開くと、ホーム画面に追加した Casebook ではなく、Safari の画面で開く見込み。その画面の Casebook は、別の保存先（空）なので、取り込んでも、ふだんの Casebook には入らない。Casebook は、ホーム画面に追加した画面でないときにリンクでパケットを受け取ったら、そのことを知らせ、「パケットをコピー」を出す（コピーして、ホーム画面の Casebook で受け取る）。iPhone で診て iPad の Casebook に入れる場合も、クリップボード（ユニバーサルクリップボード）か、共有で運べる。
- 同一オリジンにして、保存先を共有する（箱）は A-042 で決めた。iPhone・iPad で、ホーム画面に追加した2つのアプリが、同じ保存先を使えるかは、使って確かめる（A-021）。
- Casebook は、クリップボードを**本人が押したときしか読まない**。パケットでない中身（ほかの用でコピーした文字）は、画面にも保存にも出さない。

## 3. 構造（案、版 1）

```ts
type HandoffPacket = {
  magic: 'CBH1';
  schemaVersion: 1;
  packetId: Ulid;                 // 受領の冪等性に使う
  target:
    | { mode: 'new' }
    | { mode: 'append'; caseCode: string };   // 症例コード（A-007）
  patient?: { ageYears: number; sex: 'M' | 'F' | 'other'; setting: 'inpatient' | 'outpatient' | 'emergency' };   // mode が new のときだけ
  synthetic?: true;               // 架空症例として作る（T059、A-070）。mode が new のときだけ。false は書かない（なければ実症例）
  hospitalDay?: number;           // この送信の時点の病日（入院日＝第1病日）
  items: HandoffItem[];
};

type HandoffItem = {
  itemId: Ulid;                   // 項目ごとの冪等性。Casebook の要素 ID の元になる
  day?: number;                   // 病日。入院前は 0 以下（入院N日前 = 1 - N。0 は入院1日前）。入院・救急の症例で使う。なければ、パケットの hospitalDay を使う
  date?: string;                  // 受診日 'YYYY-MM-DD'。外来の症例だけ（A-023）。day と date は、どちらか1つだけ
  problemId?: Ulid;               // この項目が属するプロブレムの要素 ID（T050、A-061）。プロブレムの項目の itemId（同じパケットのものか、すでに Casebook にあるもの）。プロブレム・診断・背景には付けない
  afterMin?: number;              // 経過分（T044、A-054。第2病日以降は T047、A-058）。0〜1439 の整数。day: 1（第1病日）と date（外来の受診日）は来院（入院）時刻から（0 は来院時）、day: 2 以上はその病日の始まりから（0 は日の始まり）。入院前（day が 0 以下）と day のない項目には付けない。暦日でも時刻でもない相対の値
  source: 'rule' | 'user' | 'ai'; // どこから来たか（表示に使う。AI は確認済みのものだけ）
  body: ItemBody;
};

type ItemBody =
  | { kind: 'problem'; text: string; region?: string }                // region：訴え・病態の身体の領域（T048、A-059）
  | { kind: 'diagnosis'; text: string; status: 'suspected' | 'confirmed' }
  | { kind: 'lab'; name: string; value: number; unit: string }       // name は検査項目カタログのキー
  | { kind: 'vital'; name: string; value: number; unit: string }
  | { kind: 'finding'; text: string; polarity: 'positive' | 'negative'; region?: string }  // 診断上重要な陽性・陰性所見。region：身体の領域（T048、A-059）
  | { kind: 'imaging' | 'culture' | 'pathology' | 'ecg'; text: string }
  | { kind: 'score'; name: string; text: string }                     // 例：CURB-65：3
  | {                                                                // 治療（T046、A-057：名前以下は構造化の欄。どれも任意）
      kind: 'treatment';
      text: string;                                                  // 人が読む1文（名前と補足）。これまでどおり
      change?: 'start' | 'stop' | 'modify';
      reason?: string;
      name?: string;                                                 // 名前（補足を除く）。1〜100字。ほかの構造化の欄を付けるなら必須
      category?: 'drug' | 'procedure' | 'device';                    // 種類：薬・投与／処置・手技／器具（ライン・チューブ・ドレーンなど付けている間続くもの）
      site?: string;                                                 // 部位。1〜100字（例：右内頸静脈）
      dose?: string;                                                 // 用量。1〜100字（例：1 g 8時間ごと）
      closes?: Ulid;                                                 // 中止（change: 'stop'）だけ：終える開始の itemId
      region?: string;                                               // 身体の領域（T048、A-059）。ライン・ドレーンなどを付けた場所。付けるなら name が要る
    }
  | { kind: 'course'; text: string }                                 // Timeline に入れる経過
  | { kind: 'note'; text: string }                                   // 本人の1行メモ
  | {                                                                // 背景（T041a、A-051）。日（day・date）を持たない
      kind: 'history';
      section: 'past' | 'medication' | 'allergy' | 'social' | 'family';   // 既往歴・常用薬（内服）・アレルギー・生活歴・家族歴
      text: string;                                                  // 下の表。1行の文
      note?: string;                                                 // medication だけ：用量などの短いメモ
      allergyStatus?: 'none' | 'present' | 'unknown';                // allergy だけ（必須）
    };
```

**背景（`history`）の区分**（`section`）。1項目＝1つの事実（1つの病名、1つの薬、1つのアレルゲン）。まとめて1項目にしない。

| `section` | 意味 | `text` | `note` | `allergyStatus` | Casebook の入り先 |
|---|---|---|---|---|---|
| `past` | 既往歴 | 1行の文（空でない）。年は「N年前」「N歳時」。暦日は書かない | なし | なし | `clinical.history.entries` |
| `medication` | 常用薬（内服） | **一般名**（空でない。商品名は避ける） | 用量などの短いメモ（任意。例「5 mg 朝」） | なし | `clinical.history.meds`（`genericName`、`note`） |
| `allergy` | アレルギー | 内容（原因と症状。例「ペニシリン系で発疹」）。`none`・`unknown` では空でよい | なし | **必須**：`none`（なし）・`present`（あり）・`unknown`（不明） | `clinical.history.entries` |
| `social` | 生活歴・社会背景 | 1行（一般化した語だけ） | なし | なし | `clinical.history.entries` |
| `family` | 家族歴 | 1行（続柄だけ。人の名前は書かない） | なし | なし | `clinical.history.entries` |

**来院後の経過分（`afterMin`。T044、A-054）**：同じ日の中の前後（来院時の血圧と、治療後の血圧など）を残すための任意の欄。

- 値は**経過分**（整数、0〜1439）。**起点は日で決まる**（T047、A-058）：第1病日（`day: 1`）と外来の受診日（`date`）は**来院（入院）時刻から**（0 は来院時）、**第2病日以降（`day` が 2 以上）は、その病日の始まりから**（0 は日の始まり）。**時計の時刻は運ばない**（暦日でも時刻でもない相対の値なので、A-023 とぶつからない）。第2病日以降の「日の始まり」は、Casebook の時間の軸（第N病日の始まり ＝ (N−1)×1440 分）の近似で、時計の0時とは言わない。
- **入院後の病日（`day` が 1 以上）か、外来の受診日（`date`）の項目だけ**に付ける。入院前（`day` が 0 以下）・`day` を持たない項目（`hospitalDay` に頼る項目、背景）に付いていたら、形の違う項目として除く。
- 受け取り側は、同じ日の項目を**経過分の順に並べ**（経過分のない項目が先）、値の文に「（来院後30分）」（第2病日以降は「（日の始まりから30分）」）を添える。経過分は、事実（`lab`・`vital`・`finding`・`imaging`・`culture`・`pathology`・`ecg`・`score`）と経過（`treatment`・`course`・`note`）に残す。
- **古い Casebook は、`afterMin` つきの項目を、形の違う項目として除く**（項目の形が厳密なため。ほかの項目は取り込める）。Casebook を先に更新してから、Playbook で経過分を付ける。**第2病日以降の経過分（T047）は、T044 の Casebook も、形の違う項目として除く**（第1病日の項目だけを許していたため）。Casebook を先に更新してから、第2病日以降に付ける。

**治療の構造化の欄（T046、A-057）**：「処置・投与」の帯（A-056）を、文の一致ではなく、構造で対にするための任意の欄。

- 欄は `name`（名前。補足を除く）・`category`（種類）・`site`（部位）・`dose`（用量）・`closes`（終える開始）。**どれも任意**。`text` は、これまでどおり人が読む1文で、必須（構造化の欄がなくても、文だけで読める）。
- **`name` 以外の欄を付けるときは、`name` が要る**。`closes` は中止（`change: 'stop'`）だけ。形に合わない項目は、形の違う項目として除く。文字列は 1〜100 字。
- 受け取り側は、`name` があれば、経過（Timeline）の項目に構造化の欄を残し、「名前＋部位」を鍵に、開始と中止を対にする（補足や用量が違っても同じ行。用量の変化は帯の途中の変更）。中止が `closes` で開始を指していれば、その開始と同じ行で閉じる（指す開始が症例になければ、名前＋部位の鍵で探す）。
- **欄は、Playbook の語彙と本人の入力から作る**（ルールで推測して作らない。AI に作らせない）。匿名化リンタは、`name`・`site`・`dose` にも掛かる。
- **古い Casebook は、構造化の欄つきの治療を、形の違う項目として除く**（`afterMin` と同じ）。Casebook を先に更新してから、Playbook で構造化の欄を付ける。
- 固定のテスト用パケット：`fixtures/synthetic/handoff/new-emergency-treatment-detail.json`。

**身体の領域（`region`。T048、A-059）**：訴え・所見・ライン・ドレーンの**身体の場所**を、身体の模式図の領域として運ぶ任意の欄（Casebook で「何がどこに接続されているか」「訴えがどの部位か」を図で見せるための土台）。

- 値は**領域の ID**（`config/body-regions.yaml` の `id`。英小文字・数字・ハイフンで、英字で始まり、40字まで。例：`neck-right`、`iliac-right`、`chest-left`）。領域は、頭頸部・胸部・腹部（9区分）・骨盤・鼠径・背部・上肢・下肢（約 38）。語彙は Casebook が持ち、Playbook にコピーする（直すのは Casebook）。図形は目安の模式で、解剖の正確な境界ではない。
- 付けられるのは、**プロブレム（`problem`）・所見（`finding`）・治療（`treatment`）**だけ。治療は、ほかの構造化の欄と同じく、付けるなら `name` が要る。ほかの種類に付いていたら、形の違う項目として除く。**`site`（部位の文字）とは別の欄**：`site` は人が読む部位（「右内頸静脈」）、`region` は図に置くための領域（`neck-right`）。
- 受け取り側は、症例に残す（プロブレム・所見の事実・治療の構造化の欄）。**知らない領域の ID（新しい版の語彙のもの）は、捨てずに残し、図には出さない**。症例ビューの「処置・投与」の行に、領域の名前を出す（知っているときだけ）。J-OSLER の出力・AI の材料には出さない。
- **古い Casebook は、`region` つきの項目を、形の違う項目として除く**。Casebook を先に更新してから、Playbook で領域を付ける。
- 固定のテスト用パケット：`fixtures/synthetic/handoff/new-emergency-region.json`。

**プロブレムへの紐づけ（`problemId`。T050、A-061）**：経過・値・所見・治療が、**どのプロブレムのためのものか**を運ぶ任意の欄（Casebook の回診・再診で「このプロブレムの処置・値」をまとめるための土台。Playbook の回診のカードが付ける）。

- 値は、プロブレムの項目の `itemId`（＝ Casebook の要素 ID）。付けられるのは、**プロブレム・診断・背景以外の項目**（検査値・バイタル・所見・画像・培養・病理・心電図・スコア・治療・経過・メモ）。プロブレム・診断・背景に付いていたら、形の違う項目として除く。
- 受け取り側は、**そのプロブレムが、症例にすでにあるか、同じ（まとめて取り込む場合は前の）パケットで取り込むものなら**、経過・値・所見の `problemIds`（プロブレムへの紐づけ）に入れる。**ないとき（知らない ID・取り込まれない・消した）は、紐づけずに取り込む**（項目は落とさない）。
- **古い Casebook は、`problemId` つきの項目を、形の違う項目として除く**（厳密な形のため）。Casebook を先に更新してから、Playbook で付ける。
- 固定のテスト用パケット：`fixtures/synthetic/handoff/new-inpatient-problem-link.json`。

**架空症例（`synthetic`。T059、A-070）**：書籍から作った症例や、試しに作った症例を、**実症例と混ぜずに**運ぶための、パケットの任意の欄。

- 値は `true` だけ（`false` は書かない。ないものは実症例）。付けられるのは、**新しい症例（`mode: 'new'`）のパケットだけ**。追加（`append`）に付いていたら、パケットの形が違うものとして全体を拒む（症例の `synthetic` は、作成時から変えない。04-data-model.md の 7）。
- 受け取り側は、`true` のとき、症例を**架空症例として作る**（`Case.synthetic = true`）。確認画面に、そう出す（「架空症例として作ります。試し用で、29枠ボードなどの候補から、既定では外れます」）。本人がここで実症例にすることはできない（取り込まないか、送り直す）。
- 追加のパケットを、架空症例の症例コードに送ることはできる（症例の種類は、パケットではなく、宛先の症例が決める）。
- **送る側は、本人が「架空症例」と決めたときだけ付ける**（実症例に付けると、J-OSLER の登録の候補から外れる〔安全側〕。付け忘れると、架空症例が実症例の一覧に混ざる〔危険側〕）。Playbook は付けない（実症例を診る道具のため）。clinical-RAG は、書籍から作った架空症例から作ったことが分かるときに、本人の確認つきで付ける。
- **古い Casebook は、この欄つきのパケットを拒む**（外側の形が厳密なため）。Casebook を先に更新してから送る。
- 固定のテスト用パケット：`fixtures/synthetic/handoff/new-emergency-synthetic.json`。

- 区分と合わない欄（`medication` 以外の `note`、`allergy` 以外の `allergyStatus`、`allergy` の `allergyStatus` なし）がある項目は、形の違う項目として除く。
- **背景の項目は、`day` も `date` も持たない**（時期は文の中で「N年前」「N歳時」と書く）。付いている項目は、形の違う項目として除く（4 の 2）。`hospitalDay` も使わない。

- `status: 'suspected'` の診断は、Casebook では下書きの扱いにする（確定診断名には疑い病名と略語を使えない：J-OSLER の様式）。
- 文字列の長さの上限：1項目 500字（`text`、`note` それぞれ）。パケット全体で 100項目。【案】
- 暦日は、外来の `date` だけ（背景は日を持たない）。氏名、患者ID、施設名の欄はない。文章の中の暦日は、匿名化リンタが error にする。Playbook が自由記載を受け付けるときは、パケットを作る前に匿名化リンタを掛け、error は送れない。

## 4. 受け取り側（Casebook）の規則

0. `day` と `date` の規則：症例の `setting` が外来なら `date` だけ、それ以外なら `day` だけ。合わない項目は取り込まず、知らせる。
1. 検査：`magic` と版と CRC。新しい主版は拒む。古い版は読める限り読む。
   - **版の規則**（T041a で明文にした。A-051）：**追加だけの変更**（新しい `kind`、`history` の新しい `section`、任意の欄）では、`schemaVersion` を**上げない**。受け取り側は、知らない `kind`・`section` の項目を、捨てずに「対応できなかった項目」として別に残す（6）ので、古い Casebook でも壊れず、読める項目は取り込める。版を上げると、古い Casebook は**パケット全体を拒む**ので、読める項目まで失う。主版を上げるのは、既存の項目の意味や必須の欄を変える・消すときだけ。
   - 古い Casebook（背景を知らない版）に背景の項目が届くと、背景は取り込まれず（「知らない種類の項目」に数えられる）、ほかの項目だけが入る。そのパケットは受領済みになる。背景を入れたいときは、Casebook を更新してから取り込む。
2. スキーマ検査（zod）：形の違う項目は、数えて除き、本人に知らせる。経過分（`afterMin`）は、整数で 0〜1439、かつ `day: 1` か `date` の項目だけ（3 の「来院後の経過分」）。治療の構造化の欄（`name` 以外を付けるなら `name` が要る、`closes` は中止だけ、各 1〜100 字、種類は3つのどれか）も同じ。身体の領域（`region`）は、領域の ID の形で、プロブレム・所見・治療だけ（治療は `name` が要る）。背景（`history`）では、区分と合わない欄（3 の表の下）、空の `text`（`allergy` を除く）、`day`・`date` が付いている項目も、形の違う項目として除く。
3. 匿名化リンタ：全ての文字列に掛ける。error は、その項目を取り込まない。
4. 本人に**確認画面**を出す。項目の一覧を、種類別に表示し、選んで取り込む。AI 由来（`source: 'ai'`）は印を付け、初めは選ばない。リンタが止めた項目は、規則の名前だけを出す（中身は出さない）。
5. 取り込み：選んだ項目を、操作（Op）にして症例へ追加する。
   - 要素 ID は `itemId` と同じ。同じパケットを2回入れても重複しない。要素の ID がすでにある項目は取り込まない（あとで直した内容を上書きしない）。**取り込み済みの項目の ID（受領の記録の `itemIds`）も「取り込み済み」とみなす**：取り込んだあとに本人が消した項目も、同じパケットを入れ直して戻ることはない。
   - **背景（`history`）の取り込み先**（A-051）：`medication` は常用薬の一覧（`clinical.history.meds`。`genericName` ＝ `text`、`note` ＝ `note`、なければ空）に、それ以外の区分は背景の一覧（`clinical.history.entries`。`section`、`text`、`allergyStatus`）に、**要素の ID ＝ `itemId`** で `add` する。本人の文章欄（既往歴・家族歴・生活歴）とアレルギーの欄（状態・内容）には書かない（書くと、本人が直した内容を上書きし、2台で同じパケットを入れると文章が食い違うため）。症例の画面・出力・完成度は、文章欄と背景の一覧の両方を数える。
   - 背景の `text`・`note` は、空白と改行の連なりを空白1つにして取り込む（1行の文）。匿名化リンタは、`text` と `note` の両方に掛ける（error の項目は取り込まない）。背景は日を持たないので、日の種類の検査と受診日の範囲の検査は掛けない。外来の症例にも取り込める。
   - 受領の記録は、`handoffs` のリストへの `add`（要素 ID は `packetId`）。
   - `mode: 'new'` は、症例を作成し、症例コードを返す。画面に出して、本人が紙の台帳に書けるようにする。`synthetic: true` のパケットは、**架空症例として**作る（T059、A-070）。
   - `mode: 'append'` で、症例コードが見つからなければ、拒む。
6. 知らない `kind` は、捨てずに「対応できなかった項目」として一覧に残す。`history` の知らない `section`（将来の区分）も同じに数え、`history/<区分>` の名前で残す（形の違う項目にはしない）。

## 5. Playbook 側の規則

- 送信用の項目は、**ルールで決定論的に**抽出する：
  - 診断・Problem の追加
  - 閾値を越えた検査値
  - 治療の変更
  - 本人が書いた1行メモ
  - 背景（既往歴・常用薬・アレルギー・生活歴・家族歴。本人が入れたものだけ。T041a、A-051）
- 既定は「前回の送信からの差分」。何を送るかは、本人が項目ごとに選ぶ。
- AI による抽出は任意の補助。使うときは、元の入力と並べて確認させる。
- 送信後、Playbook は症例コードだけを session に覚える。症例の内容は戻さない。
- 症例コードは、Casebook の Active Case 一覧から本人が選ぶか、貼り付けて入れる。

## 5b. Playbook 以外の送る側（clinical-RAG。T059、A-070）

- パケットの形・検査・受け取りの規則は、Playbook と同じ。**clinical-RAG は別のオリジンで配信する**ので、受け渡し箱（handoff-box.md）は使えない。運ぶ経路は、**クリップボード（経路 2）と貼り付け（経路 3）だけ**（箱・リンクは使わない）。
- 送る項目は、本人が選んだものだけ。AI の草案から採用した項目は `source: 'ai'`、本人が書いたものは `source: 'user'`（確認画面で、AI 由来は初めは選ばれない）。**検査値・バイタル（`lab`・`vital`）は、本人が入れた値だけを、そのまま**（AI が数値を転記・要約する経路は作らない）。
- 症例コードは、箱の `returns` では返らない（別オリジン）。取り込み完了の画面の「症例コードをコピー」で、送る側に貼る。

## 6. 範囲外（後で決める）

- Casebook → Playbook の知識の昇格（レビュー付き。D-010）。
- Casebook → Playbook の最小スナップショット（A-018、D-013）。逆向きのパケットとして、別の文書に置く（設計案：[snapshot.md](snapshot.md)。D-036）。
- パケットの暗号化。匿名化済みのテキストなので、既定では行わない。

## 7. Playbook 側の実装の手引き（送る側。T028）

- **参照の実装**：Casebook の `packages/core/src/handoff/`（`packet.ts` の `encodePacket`・`decodePacket`、`codec.ts`）。Playbook は、コピーして使う（共有の依存は作らず、必要なものだけをコピーする。A-015 と同じ考え方）。契約の試験は、Casebook の `packages/core/test/handoff/` と、固定のテスト用パケット（`fixtures/synthetic/handoff/`。`synthetic: true`）。Playbook も、同じパケットが読めることを、試験にする。
- **「Casebook へ送る」ボタン1つの動き**：
  1. 前回の送信からの差分から、**ルールで**項目を作る（5 節）。送る前の確認は1画面（項目の一覧。初めからすべて選んである。AI 由来の項目だけ、確認してから選ぶ）で、ここで「送る」を押す。
  2. 匿名化リンタを、すべての文字列に掛ける。error の項目は送れない（規則の名前だけ出す）。
  3. `encodePacket`。念のため、`decodePacket` で読み戻し、形が違う項目・知らない `kind` が 0 件であることを確かめる。
  4. パケットを、**箱の `outbox` に置く**（経路 0）。同時に、クリップボードへコピーする（経路 2。箱が使えない端末のため）。
  5. 箱に置けたときは、「Casebook に送りました。Casebook を開くと、届いたと出ます」と出す。箱に置けなかったときは、「コピーしました。Casebook を開いて『Playbook から受け取る』を押してください」と出す。リンク（経路 1）は、使わなくてよい。
- **症例コード**：初回は `mode: 'new'`（`patient` と、ふつうは `hospitalDay` を付ける）。Casebook は、`hospitalDay` から入院日の初期値を逆算する（今日 −（病日 − 1））ので、入院中の症例では、`hospitalDay` を必ず付ける。取り込みのあと、Casebook は症例コードを、箱の `returns` に置く（handoff-box.md。A-042）。Playbook は、送ったパケットの `packetId` の項目を読んで、症例コードを session に入れる（読んだら消す）。2回目からは `mode: 'append'`、宛先はその症例コード。箱が使えない端末では、Casebook の取り込み完了の画面の「症例コードをコピー」で、Playbook に貼る。
- `itemId` と `packetId` は ULID。**同じ内容を2回送っても重複しない**ように、項目の `itemId` は、Playbook の項目に付けた ID を使い回す（送るたびに作り直さない）。
- **来院後の経過分（`afterMin`）を送るとき**（T044、A-054。Playbook の P021h）：
  - 本人が項目に「来院後N分」（第2病日以降は「その病日の始まりからN分」）を入れたときだけ付ける（ルールで推測して作らない）。**入院後の病日（`day` が 1 以上）か外来の受診日（`date`）の項目だけ**。入院前の日の項目には、入れさせない。
  - 同じ項目を、あとで経過分だけ直したとき、`itemId` は同じなので、取り込み済みなら取り込まれない（受け取り側は、あとで直した内容を上書きしない。契約の 4 の 5）。送る前に直す。
  - **Casebook を先に更新**する（古い Casebook は、経過分つきの項目を除く）。
  - 固定のテスト用パケット：`fixtures/synthetic/handoff/new-emergency-after-min.json`。
- **治療の構造化の欄を送るとき**（T046、A-057。Playbook の P055）：
  - 欄は、本人が入れた治療の項目（名前と補足の選択肢）から、ルールで決める：名前は語彙の名前、種類は語彙の分類、部位は部位の選択肢、用量は本人が書いた数値の部分。**語彙から決められないものは付けない**（推測しない）。`text` は、これまでどおり1文で送る。
  - 中止を送るとき、対応する開始が同じ session にあれば、その `itemId` を `closes` に入れる。開始が別の session で送られたもの（`itemId` が分からない）は、`closes` を付けず、名前と部位で対にする。
  - **Casebook を先に更新**する（古い Casebook は、構造化の欄つきの項目を除く）。
- **背景（`history`）を送るとき**（T041a、A-051。Playbook の P014）：
  - 区分は `past`・`medication`・`allergy`・`social`・`family` の5つ。**1項目＝1つの事実**（病名ごと、薬ごと、アレルゲンごとに別の `itemId`）。区分と合わない欄（3 の表）を付けない。
  - **`day`・`date`・`hospitalDay` を付けない**。時期は文の中で「N年前」「N歳時」と書く。暦日（年月日）は、書かない（匿名化リンタが error にする）。
  - `medication` の `text` は**一般名**（用量は `note` に、短く）。施設名は書かない（必要なら「当院」「近医」「前医」）。家族歴は続柄だけで、人の名前を書かない。
  - `allergy` は `allergyStatus` が必須。「なし」「不明」も、項目として送る（`text` は空でよい）。送らないと、Casebook では「未入力」のままになる。
  - 初回（`new`）にも、追加（`append`）にも付けてよい。背景は、本人が Playbook に入れたものだけを送る（ルールで推測して作らない）。AI が整理した項目は `source: 'ai'` にして、元の入力と並べて確認させる。
  - 送る前の確認画面では、背景を区分ごとに並べる。1パケット 100 項目の上限は、ほかの種類と合わせて数える。
  - 参照の実装：Casebook の `packages/core/src/handoff/packet.ts`（`HISTORY_SECTIONS`）。固定のテスト用パケット：`fixtures/synthetic/handoff/new-inpatient-history.json`。
