# 03 構成と、作る順序

状態：段2（AI の整理）、段3a〜3e（問題の筋・いまの状態・問題に書かれた値と薬・回診リスト・事実を直す操作）、本人の調節（CA-029）、段I（カルテ記載：出す・直す・相談・保存。CA-054）、いま・記録の縮め（CA-055）、段J（AI による振り分けと時系列〔CA-056〕・AI のプロブレムリスト〔CA-057〕）まで実装した。ほかは案。

## 1. 構成（案）

| 部分 | 中身 |
|---|---|
| `packages/core` | 純関数だけ（DOM・保存・通信・時計・乱数に触れない）。型と検証（zod）、識別情報の形の検査、検査値・バイタルの読み取り、日時の扱い、AI の答えの確かめ、見方（フローシート・推移・時間軸・自動の見出し）の計算 |
| `apps/worker` | Cloudflare Workers。入口の鍵、API、保存（D1）、Anthropic の API の呼び出し |
| `apps/web` | 画面（React＋Vite の PWA）。iPhone・iPad・PC（CA-017） |

- TypeScript（strict）、pnpm workspaces、Vitest と fast-check、ESLint で core の境界を止める（Casebook・Playbook・Atlas と同じ）。
- **検査と確かめの関数は core に1つだけ**：画面もサーバーも、同じ関数を import する。RAG では画面（JS）とサーバー（TS）が別の実装で、同じ試験の入力を両方に通して揃えていた（双子）。carte は最初から1つにする。
- 保存は Cloudflare D1（CA-011）。RAG と同じ基盤で、本人のアカウントにある。
- phi-guard とフックは、Casebook から写す。試験と見本は、架空症例だけ。
- **表は、サーバーが自分で用意する**（`apps/worker/src/schema.ts`）：最初の要求のとき、まだ適用していない migrations を、番号の順に適用し、名前を `schema_migrations` に控える（1件ごとに、全部できるか、全部できないか）。配る人が、表を作るコマンドを打たなくてよいようにするため（Cloudflare が自動で配るときの権限には、D1 が入っていない。docs/05）。表を作る SQL の正本は `apps/worker/migrations/*.sql` で、サーバーが読むのは、その写し（`migrations.gen.ts`。`node scripts/build_migrations.mjs` が作る。手で直さない）。**migrations に、表や中身を消す文を書かない**（配り直しで、記録が消えないように。試験が見張る）。
- **合鍵は、画面で作れる**（`apps/web/src/KeyMaker.tsx`）：サーバーに合鍵がないときだけ、端末の中で乱数から作り、コピーできる（どこにも送らない・保存しない）。コマンドを使わずに配るため。

## 2. 入口（CA-016・CA-019。段0 で実装）

- 端末ごとに最初の1回、長い合鍵を入れる。サーバーは、長い期限の印（画面のプログラムからは読めない Cookie）を出す。以後、ログインの画面は出ない。
- 合鍵はサーバーの秘密（`CARTE_KEY`）に置き、リポジトリに置かない。端末の印は、端末ごとに別で、別の端末から外せる。
- **鍵なしで動かさない**：合鍵の設定がない・32文字より短い・字の種類が少ないときは、`/api/health` も含めて、すべての API を断る。
- iPhone・iPad では、ホーム画面に足したアプリと Safari とで、印の置き場が別になる【推論。実機で確かめる】。使う側で1回ずつ登録する。

細目（`packages/core/src/entrance/entrance.ts`・`apps/worker/src/entrance.ts`・`handler.ts`。試験は `apps/worker/test/entrance.test.ts`・`apps/web/e2e/entrance.e2e.ts`）：

| 項目 | 決まり |
|---|---|
| 印 | `__Host-carte`。HttpOnly・Secure・SameSite=Strict・Path=/。期限 400 日で、使った日に延びる（延ばすのは1日に1回） |
| 印の中身 | 端末の id と、端末ごとの秘密（32バイトの乱数）。サーバーは、秘密のハッシュだけを持つ |
| 合鍵の照合 | ハッシュどうしを、最後の字まで比べる |
| 合鍵の間違い | 日ごとに数える（日付と整数だけ）。1日に 20 回で、その日は登録を受け付けない（登録済みの端末は使える）【仮の値】 |
| 端末の数 | 10 台まで【仮の値】。同じ端末がもう一度登録すると、古い登録と入れ替わる |
| 端末の種類 | iPhone・iPad・PC・その他から選ぶ（自由な名前を、入口の表に残さない） |
| 書き込みの要求 | 自分のオリジンの画面からだけ（Origin・Sec-Fetch-Site を確かめる。本文は JSON だけ） |
| 誤りの答え | 名前だけ（`unregistered`・`wrong_key` など）。何が起きたかの文を、答えにもログにも出さない |

- 残る弱み【事実】：合鍵を知らない者でも、1日に 20 回わざと間違えれば、その日の**新しい端末の登録**を止められる（登録済みの端末と記録には届かない）。

## 3. AI の呼び出し（CA-012・CA-022。段1 で実装）

- 呼ぶのはサーバーだけ（`apps/worker/src/anthropic.ts` の1か所）。キーはサーバーの秘密（`ANTHROPIC_API_KEY`。`CARTE_api_key` の名前でも読む。両方あれば `ANTHROPIC_API_KEY`。`index.ts` の `anthropicKeyOf`）。画面には出さない。
- **段1 で AI がするのは、選別だけ**（docs/01 の 2）：識別情報の場所（種類と、文の中の引用）を返す。文を書かせない。答えは、構造化した出力で受け、core の `applySelection` が確かめて、決まった語に置き換える。
- **送るもの**：指示（`apps/worker/src/prompt.ts`）と、その1回に打った文だけ。患者の年齢・性別・ほかの記録は、送らない。
- 指示は `prompt.ts` の1か所。必須の部分と、版（`SELECT_PROMPT_VERSION`）と中身の組を、`apps/worker/test/prompt.test.ts` が固定する。変えるときは、版を上げ、変更の前後で評価を見る。

| 項目 | 決まり |
|---|---|
| モデル | `claude-opus-5-5`（設定 `MODEL` で変えられる。CA-022） |
| 深さ | `effort: medium`（このモデルの既定を、明示して使う。指し漏れは記録に残るので、low にしていない）【評価を見て決める。CD-016】 |
| 断られたとき | 安全の仕組みが、医療の文を誤って断ったとき、同じ依頼を、別のモデルでやり直す（API の `fallbacks: "default"`。行き先は API が選ぶ。同じ Anthropic の API の中）【CD-015】 |
| キャッシュ | 指示は毎回同じなので、キャッシュに載せる |
| 1日の上限 | 設定 `DAILY_AI_LIMIT`（仮に 300）。呼んだ回数は `usage_daily`（日付と整数だけ）。失敗した選別も数える |
| 失敗 | AI が断った・つながらない・答えが形に合わない・引用が文と合わない → **その文は保存しない**。画面に残し、もう一度送れる |
| ログ | 送った文・AI の答えを、保存もログもしない |

### 整理（段2。`apps/worker/src/organize.ts`・core の `organize/`・`time/when.ts`）

- **いつ**：文を保存したあと、画面が続けて `/api/sources/:id/organize` を呼ぶ（保存と整理を分けた：整理に失敗しても、文は保存されている。あとから「整理する」で、いつでも整理し直せる）。
- **送るもの**：保存した文（識別情報を置き換えた後）だけ。選別のときに送った文より、増えるものはない。
- **AI が返すもの**（core の `OrganizeAnswer`）：記載の種類（未分類の文だけに使う）、記載の日時の引用、区切り（見出しと、始まりの引用）、投薬（名前・用量・動き・日時の引用）、できごと（種類・引用・日時の引用）、問題（名前の引用・書かれた確からしさ）、測定値（引用・日時の引用）。**文・数・日時そのものは返させない**。
- **確かめ**（core の `applyOrganization`）：引用が文にある（1〜200 字、改行をまたがない）。事実の文字は、文のその場所の字。測定値は、引用を `readLabText` で読む（検査結果・バイタルの文は、文全体を読む）。日時は、引用を `parseWhen` で読む（年月日・月日〔年は、記載の日にいちばん近い年〕・時刻・今日／昨日・前日／翌日など・N日前・N週間前・入院N日目／第N病日。「6時間後」の「6時」は時刻にしない。年と月だけの書き方〔「2026年6月」〕は読まない。読めなければ日時なし）。日時の引用がなければ、記載の日時。事実の文字に、識別情報の形があれば使わない。
- **区切りの時刻と記載の時刻**（CA-045。organize-5）：AI は区切りごとに、その区切りの時刻の場所（`segments[].when`）を返す。区切りの中で自分の日時のない事実（測定値・投薬・できごと。検査結果の文の読み取りも）は、その区切りの時刻。記載の時刻（`when`）は、入れたときに日時が分からなかったときと、日だけで入れたとき（同じ日の時刻があるときだけ）に使う。
- **触れ直した薬・見出しの行**（CA-046。organize-5）：A・一行要約・考察・鑑別で触れ直した薬（分類名を含む）は返さない。1つの見出しの行は1つの問題。
- **尿の検査**（CA-041。organize-4）：AI は測定値に `specimen`（尿なら urine）を付ける。尿と指された引用は、尿の項目の名前で読む（core の `readLabText` の `specimen: 'urine'`：表の「尿…」の名前から「尿」を除いた形と、白血球・ケトン・RBC・WBC などの別名を、血液の項目より先に読む）。検査結果・バイタルの文でも、尿と指された範囲だけは、尿の項目の名前で読み直す。
- **同じ字が文に何度も出る事実の場所**（投薬・できごと・問題）：最初の場所に決め打ちしない。手がかり（用量・日時の引用）が同じ行にある場所、その中で同じ種類の前の項目より後ろの場所（AI は文の順に返すことが多い）を選ぶ。手がかりも順もなければ、最初の場所。字はどこでも同じなので、変わるのは場所だけ（場所は、段3c の「問題の記載の範囲」に効く。以前は、問題一覧の「NSAIDs・ARBの関与」の ARB が、P の「ARB…中止」の場所になり、別の問題の薬として出た）。
- **「値として読めない部分があった」の数え方**：何も読めなかった引用と、項目の名前は読めたのに値を読めなかった引用だけを数える。「SpO2 96%（室内気）」の「室内気」のような、項目でない語が残っただけの引用は数えない。
- **確かめられなかったもの**：事実にせず、種類と理由ごとの件数だけを残す（`sources.organize_report`）。画面に「確かめられず、記録に入れなかったもの」として出る。文には残っている。
- **入れ替え**：整理し直すと、その文の行（区切り・投薬・できごと・問題・測定値）を、まとめて入れ替える。失敗したら、それまでの行を残し、失敗の印（`sources.organized = 'failed'`）を付ける。
- **見方**（保存しない。core の `organize/views.ts`）：投薬の時間軸（薬ごとに、書かれた動きを日時の順に）、問題の一覧（同じ名前をまとめ、最初と最後の日時、いちばん新しい記載の書かれ方）、できごとの並び。判定しない。
- 1つの文を入れると、AI を 2 回呼ぶ（選別と整理）。1日の上限に、どちらも数える。
- **計算の時間**（Cloudflare の無料プランは、1回の要求の計算が 10 ミリ秒まで【資料の値】）：手元で測ると、整理の確かめは、5 千字・各 80 件で 3 ミリ秒、1万5千字・各 250 件で 9 ミリ秒ほど。値の読み取りは、1万5千字で 1 ミリ秒ほど（項目名の候補を、先頭の字で絞った）。ふつうの長さの記載は収まる見込みだが、極端に長い記載では、上限に近い【本番では測っていない】。超えると、Cloudflare の誤りの画面（Error 1102 など）になる。そのときは、文を分けて入れる。
- 指示は `prompt.ts` の `ORGANIZE_SYSTEM`（版 `ORGANIZE_PROMPT_VERSION`）。整理した行には、どの版で整理したかが残る（`sources.organized_version`）。
- **整理の指示 organize-3**（2026-11-21。架空症例で、救急の初療〜ICU の記載を入れて見えた拾いすぎを止める）：
  - 問題：番号つきの一覧があれば、その一覧の問題だけ。括弧の中の補足・評価の文・鑑別・一行要約の病名、所見・症状、「〜なし」の所見、背景として触れただけの既往を、問題にしない。ruled_out は、問題として挙げたうえで「否定的」と書かれたものだけ。
  - 測定値：評価・考察・コンサルトの意見の中で挙げ直した値と、医師コールの条件・ガイドラインの基準を入れない。
  - 投薬：条件つきの指示・「追加しない」薬・入出量の内訳・総称（抗菌薬・輸液）・行為（K補正）を入れない。方針の行と時刻つきの実施の記録の両方にあれば、実施の記録だけ。
  - できごと：結果待ち・方針に並べただけの項目・評価の中の触れ直し・見出しだけの題を入れない。
  - 同じ事実は、起きた・測った・行ったと書かれた場所を1つだけ。
- **整理の評価**（CD-018。`apps/worker/eval/organize-cases.ts`・`organize-lib.ts`、`apps/worker/src/selfcheck.ts`、`apps/web/src/OrganizeCheck.tsx`）：新しく書いた架空の文（救急の初療・集中治療の経過・ふつうの SOAP・入院時）を、本番と同じ流れ（AI の整理 → core の `applyOrganization`）に通し、記録に入る行を、文ごとの決まり（「この問題は1つ」「所見は0」「乳酸は1つだけ」など）で数える。決まりを超えたら「余分」（拾いすぎ）、足りなければ「欠け」（拾い漏れ）。本人が画面から、**いまの版と前の版の指示を、同じ文で比べる**（前の版 `ORGANIZE_SYSTEM_PREVIOUS` は、評価のためだけに残す。本番の整理は、いつもいまの版）。返すのは数と決まりの id だけで、文・AI の答え・結果を保存しない（数えるのは AI を呼んだ回数だけ）。架空の文は5つ（尿の検査の ua-01 を足した）で、誤りの型すべてを覆うものではない。
- **本番の評価の記録（organize-4）**：2026-11-21、本人が画面から。尿の文（ua-01）は、organize-3 では余分と欠けが出て、organize-4 では決まりどおり。同じ日に organize-5 に上げ、前の版を organize-4 にし、評価に er-02（区切りの時刻・触れ直した薬の分類名・矢印のある見出し）を足した。
- **本番の評価の記録**：2026-11-21、本人が画面から各2回。organize-2：余分 5・4（er-01 の鑑別の候補2つ〔2回とも〕・結果待ちのできごと〔1回目だけ〕、icu-01 の入出量の内訳2つ〔2回とも〕）、欠け 0・0。organize-3：余分 0・0、欠け 0・0。前の版でも、所見・「なし」の所見・言い直し・条件つきの薬・見出しは、この短い文では起きなかった（実際の長い記載では起きた）。同じ日に、架空症例（救急初療〜ICU の1日分）を入れ直し、問題 21→9 などを本人の画面で確かめた。比べ終えたので organize-2 は消し、尿の読み分け（CA-041）で organize-4 に上げ、前の版を organize-3 にした。選別と違い、間違えても識別情報は漏れない（確かめの網で、文にない字・数・日時は入らない）。

### 見方と入れやすさ（段2 の後。`packages/core/src/views/chart.ts`・`apps/web/src/charts/`・`LatestStrip.tsx`・`QuickValues.tsx`・`templates.ts`）

- **経過表（温度板）**：患者の画面で最初に開くタブ。体温・心拍数・血圧・呼吸数・SpO2 を、同じ時間の軸に縦の段で並べ（1つの段に目盛りは1つ。2つの目盛りを重ねない）、その下に投薬（薬ごとの段）とできごとを置く。日付と、入院なら病日を上に出す。血圧は、上と下を縦の線でつなぐ。日だけ分かる値は、その日の真ん中に白抜きの点で置く。タップした時刻の値を、グラフの下にまとめて出す（指で隠れないように。位置を style で動かさない：CSP）。

### AI による振り分け（段J。CA-056。整理の指示 organize-6。`packages/core/src/organize/apply.ts`・`time/hint.ts`・`apps/web/src/CourseView.tsx`）

架空の病歴（「3日前の夕方から悪寒と発熱、熱は38.5℃まで上昇」「来院2時間前から呼吸苦」「血圧は90/50と低下」）で、決定論の読み取りが、文章の中の値・幅のある時刻・病歴の流れを落としていた。本人の決定で、生成 AI に振り分けを任せる範囲を広げた。

- **時刻の手がかり**（`whenHint`）：引用を規則で読めない言い方は、AI が基準（記載・来院）とずれ（日・時間・分）・時刻・時間帯・幅を返し、`resolveHint` が決定論で日時にする。時間帯は代表の時刻（夕方 17:00 など）、幅は日の範囲で、どちらも「ごろ」の印（`at_approx`）。規則で日だけ読めて、手がかりが同じ日の時刻・時間帯を足すときは、手がかりを使う（「3日前の夕方」）。
